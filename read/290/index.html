被盗GitHub令牌批量植入工作流，1.35万分支泄密

Wiz追踪的Gheist活动自9月15日起，用被盗GitHub令牌向令牌可达的每个仓库推送sync-check工作流，把密钥以base32写入Actions日志、再经API取走并删除运行记录；已回收850多个账号下1.35万多个分支，攻击不使用外部C2。

具体发生了什么

攻击分支名为ci-sync-加六位随机字符。GitHub只对逐字出现的密钥做日志掩码，base32编码即可完整打印；环境级密钥也会被作业矩阵带出[1]。GitHub自7月28日起对公开仓库的可疑工作流先挂起待批准，Wiz核查的公开仓库运行全部停在action_required；私有仓库与Enterprise Server不受此保护，审计日志显示运行完成并被删除[1][2]。

为什么值得看

没有外部域名、没有C2，数据经GitHub自家API流出，出站封锁和域名黑名单失效。防御单位因此下沉到每个仓库、每个环境的密钥，而不是账号本身。

分析与判断

判断：这类攻击成本极低、清理成本极高——删分支、删运行都不撤销已泄露的密钥，只能全量轮换。凭证治理粒度决定响应速度。

证据边界

受影响规模来自Wiz单方遥测，GitHub未公布对应数字；约三分之二账号已不可用，其原因为推断性解释，未获官方确认。

来源与依据

  1. Gheist事件：大规模滥用窃取GitHub令牌的尝试受挫
    受影响分支与账号规模，以及攻击手法与处置建议
  2. GitHub Actions 暂扣潜在恶意工作流待批准
    审批拦截仅覆盖公开仓库，私有仓库与Enterprise Server不在范围内
